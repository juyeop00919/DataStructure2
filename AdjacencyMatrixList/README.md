# 과제 07: 인접 행렬과 인접 리스트의 성능 비교 분석

본 프로젝트는 정점이 100개인 무방향 단순 그래프를 대상으로, 그래프의 밀도(희소/밀집)와 표현 방식(인접 행렬/인접 리스트)에 따른 메모리 사용량과 연산 성능(비교 횟수)의 차이를 측정하고 분석합니다.

## 1. 성능 측정 결과 요약

다음은 동일한 조건의 희소 그래프(간선 100개)와 밀집 그래프(간선 4,000개)를 대상으로 측정한 실행 결과입니다.

| 측정 항목 | Case 1: 희소 - 행렬 | Case 2: 희소 - 리스트 | Case 3: 밀집 - 행렬 | Case 4: 밀집 - 리스트 | 
| ----- | ----- | ----- | ----- | ----- | 
| **메모리 사용량 (Bytes)** | 40,000 | 4,000 | 40,000 | 128,800 | 
| **간선 삽입 비교 횟수** | 1 | 4 | 1 | 158 | 
| **간선 삭제 비교 횟수** | 1 | 5 | 1 | 99 | 
| **연결 여부 확인 비교 횟수** | 1 | 3 | 1 | 40 | 
| **인접 정점 출력 비교 횟수** | 100 | 0 | 100 | 85 |

## 2. 연산별 성능 분석

* **메모리 사용량 (**$O(V^2)$ **vs** $O(V+E)$**)**
  인접 행렬은 간선의 수와 무관하게 100×100 크기의 배열을 유지해야 하므로, 희소/밀집 여부에 상관없이 항상 **40,000 Bytes**를 차지합니다. 반면 인접 리스트는 간선의 수에 비례하여 메모리를 사용합니다. 희소 그래프에서는 **4,000 Bytes**로 매우 효율적이지만, 밀집 그래프에서는 각 간선마다 데이터를 저장할 노드와 포인터 구조가 필요하므로 행렬보다 3배 이상 큰 **128,800 Bytes**를 차지하게 됩니다.

* **간선 삽입, 삭제 및 연결 여부 확인**
  인접 행렬은 2차원 배열의 인덱스(`matrix[u][v]`)를 통해 특정 간선에 직접 접근하므로 **항상 1회**의 비교 연산($O(1)$)만 수행합니다. 반면 인접 리스트는 특정 간선을 찾기 위해 해당 정점의 연결 리스트를 순차 탐색해야 하므로 차수(Degree)에 비례($O(d)$)하여 탐색 횟수가 증가합니다. 이로 인해 리스트는 밀집 그래프에서 약 40\~158회의 비교가 발생하며 행렬에 비해 현저히 성능이 떨어졌습니다.

* **특정 정점의 인접 정점 출력**
  인접 행렬은 연결되지 않은 정점까지 포함하여 배열의 전체 열(100개)을 모두 검사해야 하므로 **항상 100회**($O(V)$)의 비교가 발생합니다. 인접 리스트는 실제로 연결된 간선만 리스트에 존재하므로 정점의 차수만큼만 순회하면 됩니다. 실행 결과 희소 그래프에서는 0회(해당 정점에 연결된 간선이 없어 즉시 종료됨), 밀집 그래프에서는 85회로 인접 행렬(100회)보다 항상 우수한 성능을 보였습니다.

## 3. 그래프 밀도에 따른 차이 분석

### 희소 그래프 (Sparse Graph)에서의 차이

간선이 100개로 적은 환경에서는 **인접 리스트가 인접 행렬보다 압도적으로 효율적**입니다.
인접 행렬은 연결되지 않은 98% 이상의 공간을 빈 상태(0)로 두어 메모리 낭비가 심하지만, 인접 리스트는 1/10 수준의 메모리(4,000 Bytes)만 사용합니다. 각 정점에 연결된 간선이 극히 적어 삽입/삭제 시 비교 횟수(4\~5회)도 크지 않습니다. 특히 인접 정점 출력 시 연결된 정점이 없다면 탐색을 시작조차 하지 않고(비교 0회) 즉시 완료하므로, 항상 100회를 낭비하며 탐색해야 하는 행렬보다 훨씬 유리합니다.

### 밀집 그래프 (Dense Graph)에서의 차이

간선이 4,000개(최대치인 4,950개에 근접)인 환경에서는 반대로 **인접 행렬이 훨씬 우수**해집니다.
인접 리스트는 무수히 많은 간선을 저장하기 위한 Node 동적 할당과 next 포인터 오버헤드로 인해 메모리 사용량이 크게 폭증(128,800 Bytes)하여 행렬보다 공간 효율성이 떨어집니다. 또한 간선을 삽입하거나 삭제할 때 긴 리스트를 끝까지 탐색해야 하므로 100회 안팎의 잦은 비교 연산이 발생하여 연산 속도 측면에서도 행렬(1회)에 크게 뒤처지게 됩니다.

## 4. 결론: 자료구조의 적절한 사용 환경

실험 결과를 종합할 때, 어떠한 경우에 어떤 자료구조를 사용하는 것이 바람직한지 다음과 같이 결론지을 수 있습니다.

1. **인접 리스트를 사용해야 하는 경우 (희소 그래프 환경)**

   * 정점의 개수는 매우 많지만 실제 연결된 간선은 적은 네트워크(예: 지도 경로, SNS 친구 관계 등).

   * 메모리를 엄격하게 절약해야 하는 환경.

   * 특정 정점과 연결된 모든 "인접 정점들을 탐색(순회)"하는 연산이 프로그램의 주 목적일 때.

2. **인접 행렬을 사용해야 하는 경우 (밀집 그래프 환경)**

   * 정점 간의 연결이 매우 촘촘한 환경.

   * 두 정점이 "연결되어 있는지 확인"하거나 정점 간의 "간선을 삽입/삭제"하는 단일 연산이 매우 빈번하게 발생하는 환경.

   * 정점의 개수가 비교적 적어 2차원 배열을 할당하더라도 메모리 제약을 크게 받지 않는 경우.
