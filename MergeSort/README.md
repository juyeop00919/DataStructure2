# 과제 13: 병합 정렬과 퀵 정렬의 성능 비교 분석

본 문서에서는 무작위로 생성된 정수 배열(데이터 크기 $N$ = 1,000 ~ 20,000)을 대상으로 병합 정렬(Merge Sort)과 3가지 피벗 방식을 적용한 퀵 정렬(Quick Sort)을 1,000회씩 반복 측정하여 얻은 성능 결과를 비교 및 분석합니다.

(프로그램이 너무 빨리 끝나서 반복 후 /반복횟수 를 통해 시간 값을 구했습니다)

## 1. 메모리 사용량의 측정 방법과 계산 기준

본 실험에서 각 알고리즘의 메모리 사용량은 원본 배열이 차지하는 공통 공간을 제외하고 **정렬 수행 중에 추가로 발생하는 최대 메모리**를 기준으로 산정했습니다. 정확한 측정을 위해 `sizeof()` 연산자를 사용하여 시스템 환경에 맞는 바이트(Bytes) 단위 크기를 동적으로 계산했습니다.

*   **계산 기준 수식:** `동적 할당된 배열의 메모리 크기 + (최대 재귀 호출 깊이 × 스택 프레임 크기)`
*   **스택 프레임(Stack Frame) 크기:** 각 재귀 함수가 호출될 때 전달받는 매개변수(포인터 및 정수형 변수)의 타입 크기(`sizeof`) 합산
    *   Merge Sort 재귀 인자: 포인터 4개 + 정수 3개
    *   Quick Sort 재귀 인자: 포인터 3개 + 정수 3개
*   따라서 병합 정렬은 `N * sizeof(int)` 크기의 임시 배열과 재귀 호출 스택의 합으로 계산되었으며, 퀵 정렬은 추가 배열 없이 재귀 호출 스택의 크기만으로 메모리가 계산되었습니다.

## 2. 데이터 크기 증가에 따른 비교 횟수 변화

데이터 크기($N$)가 1,000에서 20,000으로 증가함에 따라 병합 정렬과 퀵 정렬 모두 비교 횟수가 기하급수적으로 증가($O(N \log N)$ 형태)했습니다. 

실험 결과, **모든 데이터 크기에서 병합 정렬의 비교 횟수가 퀵 정렬보다 확연히 적었습니다.** ($N=20000$ 기준 병합: 260,842회, 퀵(First): 329,319회)
*   **이유:** 병합 정렬은 리스트를 항상 정확히 반(1:1 비율)으로 분할하는 최적의 분할-정복을 수행하므로 잉여 비교가 발생하지 않습니다. 반면 퀵 정렬은 피벗의 값에 따라 파티션이 비대칭(예: 3:7 비율)으로 나뉠 수 있어 재귀 트리가 불균형해지고, 이로 인해 데이터를 비교하는 횟수가 이론적 최소치보다 더 늘어나게 됩니다.

### 2.2 두 정렬 알고리즘의 실행시간 차이
시간 복잡도는 모두 $O(N \log N)$이지만, 알고리즘의 부가 연산 및 하드웨어 특성에 따라 실제 실행 시간에서 흥미로운 차이가 관찰되었습니다.

*   **Quick (First)의 역설적인 속도 우위:** 
    이론상 가장 안정적인 `Median3` 방식보다 가장 단순한 `First` 방식이 전체 구간에서 가장 빠른 속도를 기록했습니다. 실험 데이터가 이미 무작위(Random)로 섞여 있었기 때문에, `First` 방식을 사용해도 파티션이 비교적 균형 있게 나뉘었습니다. 결과적으로 `Median3`에서 중앙값을 찾기 위해 소모되는 3회 이상의 `if-else` 비교 연산 오버헤드가 없는 `First`가 가장 빠르게 동작했습니다.
*   **Quick (Random)의 난수 생성 병목:** 
    `Random` 방식은 다른 퀵 정렬은 물론이고 `Merge Sort`보다도 실행시간이 느렸습니다. 매 재귀 호출마다 피벗을 선정하기 위해 `rand()` 함수와 모듈러(`%`) 연산을 호출하는 시스템적 비용이 매우 크기 때문에 발생한 현상입니다.
*   **Merge Sort의 순차 접근 최적화:** 
    병합 정렬은 매번 임시 배열을 할당하고 복사하는 메모리 오버헤드가 존재함에도 시간 지연이 치명적이지 않았습니다. 이는 데이터 복사가 순차적 메모리 접근(Sequential Access)으로 이루어져 현대 CPU의 캐시 메모리 프리패칭(Prefetching) 효율이 높게 작용했기 때문으로 분석됩니다.

## 3. 두 정렬 알고리즘의 실행시간 차이

실행 시간 측정 결과, 흥미롭게도 값 비교를 가장 적게 한 **병합 정렬보다 퀵 정렬(First, Median3)이 더 빠르게 동작**했습니다. ($N=20000$ 기준 퀵(First) 2.885ms < 병합 3.362ms)

*   **이유:** 알고리즘의 내부 동작 방식에 기인합니다. 퀵 정렬은 추가 배열 없이 원본 배열 내에서 두 인덱스의 값만 스왑(Swap)하는 **제자리 정렬(In-place Sort)**입니다. 이는 메모리 캐시 지역성(Cache Locality)을 극대화하여 매우 빠른 연산 속도를 보장합니다.
*   반면, 병합 정렬은 부분 배열을 정렬할 때마다 임시 배열(`temp`)에 데이터를 하나씩 복사해 넣고, 정렬이 끝나면 다시 원본 배열로 복사(Copy)해오는 오버헤드(Overhead)가 발생합니다. 이 메모리 I/O 작업의 누적이 값 비교에서 얻은 이득을 상쇄하여 실행 시간을 지연시켰습니다.

## 4. 두 정렬 알고리즘의 메모리 사용량 차이

메모리 사용량에서는 두 알고리즘 간에 가장 극단적인 차이가 나타났습니다. 
데이터가 커질수록 병합 정렬의 메모리는 폭발적으로 증가한 반면, 퀵 정렬은 미미하게 증가했습니다. ($N=20000$ 기준 병합 80,704 Bytes ≫ 퀵 1,188 Bytes)

*   **이유:** 병합 정렬은 병합 과정에서 원본 배열과 크기가 같은 임시 배열(`temp`)이 반드시 필요하므로 데이터 크기 $N$에 비례하여 동적 할당 메모리가 커집니다. (N=20,000일 때 임시 배열만 약 80KB 소모)
*   반면 퀵 정렬은 임시 배열이 일절 필요 없습니다. 오직 재귀 호출이 깊어짐에 따라 시스템이 쌓는 스택(Stack) 메모리만 소모하므로, $N$이 20배 증가하더라도 로그 스케일로 아주 완만하게 메모리가 증가하여 1~2KB 내외만 사용했습니다.

## 5. 퀵 정렬의 피벗 선택 방법에 따른 성능 차이

동일한 퀵 정렬 안에서도 어떤 원소를 피벗(Pivot)으로 삼느냐에 따라 성능 차이가 발생했습니다. 

1.  **Median-of-Three (가장 우수한 성능):** 전체 퀵 정렬 중 **가장 적은 비교 횟수**와 **가장 적은 메모리 사용량**을 기록했습니다. 맨 앞, 중간, 맨 뒤 세 값 중 중앙값을 피벗으로 삼아 파티션의 불균형을 사전에 방지했기 때문입니다. 트리가 얕아져 재귀 스택 메모리 소모가 최소화(1,008 Bytes)되었습니다.
2.  **First Element:** 무작위로 생성된 난수 데이터에서는 역순 정렬과 같은 최악의 상황이 발생하지 않기 때문에 준수한 파티션 분할이 이루어졌습니다. 추가적인 수학 연산이 없어서 단순 속도로는 Median3와 맞먹는 빠른 실행 시간(2.885ms)을 기록했습니다.
3.  **Random Pivot (가장 느린 실행 시간):** 비교 횟수와 메모리 사용량은 First와 비슷했지만, **실행 시간은 모든 정렬 중 가장 느렸습니다(3.475ms).** 파티션을 나눌 때마다 `rand()` 함수를 호출하고 모듈러(`%`) 연산을 수행하는 부가적인 오버헤드가 발생하여 정렬 본연의 성능을 크게 저하시켰습니다.

## 6. 병합 정렬과 퀵 정렬의 시간 및 공간 복잡도 요약

| 항목 | 병합 정렬 (Merge Sort) | 퀵 정렬 (Quick Sort) |
| :--- | :--- | :--- |
| **평균 시간 복잡도** | $O(N \log N)$ | $O(N \log N)$ |
| **공간 복잡도** | $O(N)$ | $O(\log N)$ |

*   **시간 복잡도:** 두 알고리즘 모두 평균적으로 $O(N \log N)$의 우수한 시간 복잡도를 가집니다. 단, 퀵 정렬은 피벗이 지속적으로 최악으로 선택될 경우 $O(N^2)$으로 저하될 위험이 있으나, 본 실험과 같은 무작위 데이터 혹은 Median3 방식을 사용할 경우 $O(N \log N)$의 성능을 안정적으로 낼 뿐만 아니라 캐시 효율 덕분에 실제 구동 시 병합 정렬보다 빠릅니다.
*   **공간 복잡도:** 병합 정렬은 입력 데이터만큼의 추가 메모리가 필요한 $O(N)$의 공간 복잡도를 가져 메모리 효율이 떨어집니다. 반면 퀵 정렬은 스택 메모리만을 사용하는 $O(\log N)$ 알고리즘으로, 메모리가 제한된 환경에서 압도적인 효율성을 보여줍니다.
