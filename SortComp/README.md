# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

## 1. 무작위 데이터 100회 실험 결과 및 성능 차이 원인 분석
10,000개의 무작위 데이터를 100회 반복 정렬한 결과, 세 정렬 알고리즘의 총 및 평균 비교/이동 횟수는 다음과 같습니다.

* **선택 정렬 (Selection Sort)**
  * 총 비교: 4,999,500,000회 / 평균 비교: 49,995,000회
  * 평균 이동: 29,970회
* **버블 정렬 (Bubble Sort)**
  * 총 비교: 4,999,500,000회 / 평균 비교: 49,995,000회
  * 평균 이동: 74,993,795회
* **삽입 정렬 (Insertion Sort)**
  * 총 비교: 2,500,792,222회 / 평균 비교: 25,007,922회
  * 평균 이동: 25,017,929회

**성능 차이 발생 원인 분석:**
동일한 $O(N^2)$ 시간 복잡도를 갖지만 내부 동작 방식에 따라 뚜렷한 차이가 발생합니다.
* **선택 정렬**은 탐색 영역의 최솟값을 찾기 위해 무조건 끝까지 비교를 수행하므로 비교 횟수가 최대치(약 4,999만 회)에 달합니다. 하지만 교환(이동)은 최솟값을 찾은 후 1회만 수행하므로 데이터 이동 횟수(약 3만 회)가 가장 적습니다.
* **버블 정렬**은 인접한 값을 계속 비교하고 조건에 맞으면 즉시 교환하기 때문에, 비교 횟수도 최대치이며 이동 횟수(약 7,499만 회) 역시 가장 높게 나타납니다.
* **삽입 정렬**은 비교 대상이 정렬된 영역에 들어갈 위치를 찾으면 즉시 탐색(비교)을 중단합니다. 따라서 무작위 데이터 환경에서도 평균적으로 탐색을 절반만 수행하므로 비교 및 이동 횟수 모두 버블 정렬의 약 1/3 수준으로 가장 우수한 평균 효율을 보입니다.

## 2. 일반 버블 정렬과 조기 종료 버블 정렬의 비교
* **일반 버블 정렬 평균 비교:** 49,995,000회
* **조기 종료 버블 정렬 평균 비교:** 49,985,430회
* **비교 횟수 차이:** 9,570회 감소

무작위 데이터에서는 조기 종료(Early Termination) 조건이 미치는 영향이 매우 적습니다. 데이터가 무작위로 섞여 있어 배열이 완전히 정렬되는 시점이 마지막 순회(Pass)에 가깝기 때문에 조기 종료가 거의 발생하지 않습니다. 

## 3. 안정성(Stability) 검증 방법과 결과
**검증 방법:** 
데이터 입력 시 각 원소의 원래 순서를 나타내는 `id` 값을 함께 저장했습니다. 키 중복이 발생하도록 첫 번째 키 값을 0~49로 제한한 별도의 시험 데이터를 생성한 후, 정렬 결과에서 인접한 동일 키 값을 가진 데이터 간의 `id`를 비교했습니다. 앞 데이터의 `id`가 뒤 데이터의 `id`보다 크면(원래 순서가 뒤집히면) Unstable로 판정했습니다.

**검증 결과 및 원인:**
* **선택 정렬 (Unstable):** 정렬되지 않은 배열에서 최솟값을 찾아 현재 위치의 원소와 강제로 맞바꿉니다. 이때 현재 위치에 있던 원소가 동일한 키 값을 가진 다른 원소의 뒤로 밀려나게 되어 순서가 파괴됩니다.
* **버블 정렬 (Stable):** 인접한 두 데이터를 비교할 때, 앞의 데이터가 뒤의 데이터보다 엄격히 클(`>`) 때만 교환합니다. 동일한 값이면 위치를 바꾸지 않으므로 순서가 유지됩니다.

## 4. 삽입 정렬에서 `>`와 `>=`의 사용이 안정성에 미치는 영향
* **삽입 정렬 `>` 사용 (Stable):** 비교 대상이 자신보다 '클 때만' 뒤로 밀어냅니다. 자신과 '동일한 값'을 만나면 밀어내기를 멈추고 그 뒤에 삽입되므로 원래 입력 순서가 보존됩니다.
* **삽입 정렬 `>=` 사용 (Unstable):** 비교 대상이 자신과 '같을 때도' 굳이 뒤로 밀어내고 자신이 그 앞자리를 차지합니다. 이로 인해 동일 키를 가진 데이터들의 상대적 순서가 정반대로 뒤집히게 됩니다.

## 5. 입력 데이터의 초기 정렬 상태에 따른 알고리즘 성능 영향

### [1] 이미 정렬된 데이터 (Sorted Data)에서의 성능 분석

데이터가 이미 완벽하게 오름차순으로 정렬되어 있는 최상의 조건(Best Case)에서 각 알고리즘이 어떻게 다르게 동작하는지 분석했습니다.

* **선택 정렬 (Selection Sort)**
  * **결과:** 비교 49,995,000회 / 이동 0회
  * **분석:** 데이터가 이미 정렬되어 있어도, 선택 정렬은 무조건 배열 끝까지 훑어보며 최솟값을 찾는 융통성 없는 탐색을 합니다. 따라서 비교 횟수는 무작위 데이터일 때와 똑같이 최대치를 기록합니다. 다만, 훑어본 결과 항상 현재 자리에 있는 값이 최솟값이므로 실제 자리를 맞바꾸는 데이터 이동(교환)은 단 한 번도 일어나지 않았습니다.

* **일반 버블 정렬 (Bubble Sort)**
  * **결과:** 비교 49,995,000회 / 이동 0회
  * **분석:** 일반 버블 정렬 역시 데이터 상태와 무관하게 정해진 횟수만큼 배열을 끝에서 끝까지 반복 순회하므로 비교 횟수는 최대치에 달합니다. 이미 오름차순이라 '앞의 값이 뒤의 값보다 큰 경우'가 아예 없기 때문에 교환(이동) 연산은 0회입니다.

* **조기 종료 버블 정렬 (Early Termination Bubble Sort)**
  * **결과:** 비교 9,999회 / 이동 0회
  * **분석:** 조기 종료 조건의 위력이 100% 발휘되는 구간입니다. 단 한 번의 배열 순회(9,999번 비교) 동안 교환이 한 번도 일어나지 않는 것을 감지하고, "이미 배열이 다 정렬되어 있구나!"라고 판단하여 즉시 정렬을 멈춥니다. 덕분에 약 5천만 번에 달하던 비교 연산을 만 번 이하($O(N)$)로 극적으로 줄였습니다.

* **삽입 정렬 (Insertion Sort)**
  * **결과:** 비교 9,999회 / 이동 19,998회
  * **분석:** 삽입 정렬은 자기 앞의 데이터와 딱 한 번씩만 비교해 보고 "내가 더 크니까 자리를 안 옮겨도 되네"라며 즉시 앞쪽 탐색을 멈춥니다. 따라서 비교 횟수는 9,999회로 매우 우수합니다. 
  * **이동 횟수가 0이 아닌 이유:** 실제 위치 변화는 없지만, 코드가 동작하는 구조상 현재 카드를 임시 공간에 잠깐 빼두었다가(이동 1회) 비교를 마친 후 다시 원래 자리에 그대로 꽂아 넣는(이동 1회) 불필요한 동작이 무조건 실행되기 때문에 총 19,998회의 데이터 이동이 측정되었습니다.

### [2] 역순으로 정렬된 데이터 (Reverse-Sorted Data)
* **선택 정렬:** 비교 49,995,000회 / 이동 16,842회
* **일반 & 조기 종료 버블 정렬:** 비교 49,995,000회 / 이동 149,980,341회
* **삽입 정렬:** 비교 49,994,860회 / 이동 50,013,445회

**분석:** 모든 원소가 반대로 배치된 최악의 경우입니다. 버블 정렬과 삽입 정렬 모두 매번 배열의 맨 앞까지 원소를 끌고 가야 하므로 비교 횟수가 최대치에 달하며, 특히 데이터 이동 횟수가 무작위 데이터 대비 폭증하여 극도의 비효율을 보여줍니다.

### [3] 일부 정렬된 데이터 (Partially Sorted Data)에서의 성능 분석

**부분 정렬 데이터를 만든 방법 (인공지능 활용):**
'일부만 정렬된 데이터'를 객관적으로 어떻게 만들면 좋을지 인공지능에게 질문하고, 그 조언을 바탕으로 다음과 같은 2단계를 거쳐 데이터를 생성했습니다.
1. 10,000개의 데이터를 오름차순으로 완벽하게 줄을 세웁니다.
2. 전체 데이터의 5% 정도만 무작위로 두 원소를 골라 서로 자리를 바꿉니다. 
이렇게 하면 전체적으로는 줄을 잘 서 있지만 군데군데 순서가 섞인, 실생활이나 실무에서 가장 흔하게 접할 수 있는 형태의 데이터가 완성됩니다.

이 데이터로 각 알고리즘을 테스트한 결과는 다음과 같습니다.

* **선택 정렬 (Selection Sort)**
  * **결과:** 비교 49,995,000회 / 이동 1,716회
  * **분석:** 데이터가 얼추 정렬되어 있더라도 융통성 없이 무조건 끝까지 탐색하므로 비교 횟수는 여전히 최대치입니다. 다만, 이미 제자리에 있는 원소가 많다 보니 진짜로 자리를 맞바꿔야 하는 상황이 크게 줄어들어, 데이터 이동 횟수는 무작위 데이터(약 3만 회)일 때보다 획기적으로 줄어든 1,716회에 그쳤습니다.

* **일반 버블 정렬 (Bubble Sort)**
  * **결과:** 비교 49,995,000회 / 이동 9,391,956회
  * **분석:** 무조건 끝에서 끝까지 순회하므로 비교 횟수는 최대치입니다. 무작위 데이터(약 7,500만 회 이동)보다는 덜 섞여 있기 때문에 이동 횟수가 약 939만 회로 크게 줄긴 했지만 여전히 비효율적입니다.

* **조기 종료 버블 정렬 (Early Termination Bubble Sort)**
  * **결과:** 비교 49,949,247회 / 이동 9,391,956회
  * **분석:** 전체의 딱 5%만 뒤섞였을 뿐인데도, 섞인 원소들이 제자리를 찾아가느라 거의 매 순회(Pass)마다 교환이 발생했습니다. 결국 정렬이 꽤 진행된 후반부에 가서야 간신히 조기 종료가 발동했기 때문에 일반 버블 정렬과 성능 차이가 거의 없었습니다.

* **삽입 정렬 (Insertion Sort)**
  * **결과:** 비교 3,140,651회 / 이동 3,150,650회
  * **분석:** 일부만 섞인 이 환경에서 **가장 압도적인 효율**을 발휘했습니다. 앞쪽이 이미 정렬되어 있으므로, 새로 들어갈 원소가 멀리까지 비교하러 갈 필요 없이 한두 번만 비교하면 바로 자기 자리를 찾아 멈추기 때문입니다. 완전히 뒤죽박죽인 무작위 데이터(약 2,500만 회)를 다룰 때와 비교하면 비교/이동 횟수가 약 8배 이상 폭발적으로 줄어들었습니다. 실전에서 삽입 정렬이 강력한 이유를 완벽하게 보여주는 결과입니다.
## 6. 전반적인 인공지능 활용 내용
* 정렬 함수를 구성할 때 인공지능에게 이론적인 구조를 한번 더 체크하고 구현에 참고했습니다.
* 보고서를 작성할 때 실제 실험결과가 이론적인 연산횟수와 일치하는지 확인했고 이를 토대로 작성하였습니다.
