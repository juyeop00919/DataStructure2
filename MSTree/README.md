# 과제 08: 최소 비용 신장 트리(MST) 알고리즘 성능 비교 분석

본 과제에서는 정점이 50개인 가중치 무방향 연결 그래프를 대상으로, 그래프의 밀도(희소/밀집)와 표현 방식, 그리고 MST 알고리즘(Kruskal/Prim)에 따른 이론적 성능(시간/공간 복잡도)과 실제 측정 결과의 차이를 분석합니다.

## 1. 성능 측정 결과 요약

알고리즘의 실행속도를 비교해보려고 했으나 0.0ms 와 같이 너무 빠르게 실행이 종료되어 반복연산을 사용해 비교했습니다.
이미지 수정전
이미지 수정후
| 측정 항목 | Case 1: 희소 (리스트+Kruskal) | Case 2: 밀집 (리스트+Kruskal) | Case 3: 희소 (행렬+Prim) | Case 4: 밀집 (행렬+Prim) |
| :--- | :---: | :---: | :---: | :---: |
| **정점($V$) / 간선($E$) 수** | 50 / 100 | 50 / 600 | 50 / 100 | 50 / 600 |
| **MST 포함 간선 수** | 49 | 49 | 49 | 49 |
| **MST 전체 비용(Cost)** | **1846** | **260** | **1846** | **260** |
| **메모리 사용량 (Bytes)** | 5,200 | 27,200 | 10,600 | 10,600 |
| **실행 시간 (us)** | 13.80 | 95.40 | 9.60 | 12.30 |

> **결과 정당성 확인:** 
> 동일한 희소 그래프를 사용한 Case 1과 3의 MST 비용이 1846으로 일치하고, 동일한 밀집 그래프를 사용한 Case 2와 4의 비용이 260으로 일치합니다. 또한 모든 Case에서 MST 간선 수가 $V-1$인 49개로 출력되어 알고리즘이 올바르게 동작했음을 확인했습니다.

---

## 2. 그래프 표현 방식과 공간 복잡도 분석

각 그래프 표현 방식이 메모리(공간 복잡도)에 미치는 영향을 밀도에 따라 비교했습니다.

* **인접 행렬 (공간 복잡도: $O(V^2)$)**
  인접 행렬은 간선의 개수($E$)와 무관하게 정점 수($V$)의 제곱에 비례하는 2차원 배열을 할당해야 합니다. 따라서 희소 그래프(Case 3)와 밀집 그래프(Case 4) 모두 동일하게 **10,600 Bytes**를 사용합니다.
* **인접 리스트 (공간 복잡도: $O(V + E)$)**
  인접 리스트는 실제로 존재하는 간선의 수만큼 동적으로 노드를 생성합니다. 
  간선이 적은 희소 그래프(Case 1)에서는 **5,200 Bytes**만을 사용하여 행렬보다 메모리를 크게 절약합니다. 하지만 간선이 크게 늘어난 밀집 그래프(Case 2)에서는 각 간선마다 구조체와 포인터를 유지해야 하므로, 메모리 사용량이 행렬보다 2배 이상 큰 **27,200 Bytes**로 급격히 증가합니다.

## 3. 알고리즘 특성과 시간 복잡도 분석

그래프의 밀도 변화($E=100 \rightarrow 600$)가 각 알고리즘의 실행 시간에 미치는 영향을 이론적 시간 복잡도를 통해 분석했습니다.

### ① Kruskal 알고리즘 (인접 리스트)
Kruskal 알고리즘의 핵심은 모든 간선을 가중치 오름차순으로 정렬하는 것이며, 이때의 시간 복잡도는 **$O(E \log E)$**가 됩니다. 이후 Union-Find를 통한 사이클 검사는 사실상 상수 시간에 가깝습니다.
* **분석:** 시간 복잡도가 간선의 수($E$)에 직접적으로 지배를 받기 때문에, 간선이 6배 증가하자 실행 시간 역시 13.80 us에서 95.40 us로 **약 7배 가까이 급증**했습니다. 밀집 그래프에서는 간선 정렬에 드는 비용이 지나치게 커짐을 확인할 수 있습니다.

### ② Prim 알고리즘 (인접 행렬)
본 과제에서 인접 행렬을 사용해 구현한 Prim 알고리즘은 매 단계마다 방문하지 않은 정점 중 최소 가중치를 가진 정점을 찾기 위해 $V$개의 정점을 순회합니다. 이를 $V$번 반복하므로 전체 시간 복잡도는 **$O(V^2)$**이 됩니다.
* **분석:** Prim의 연산 횟수는 간선의 수($E$)가 아닌 정점의 수($V$)에 의해 결정됩니다. 정점의 수($V=50$)가 고정되어 있기 때문에, 간선이 6배 늘어난 밀집 그래프에서도 실행 시간은 9.60 us에서 12.30 us로 **미미하게 증가**하는 데 그쳤습니다. 

### ③ 시간 복잡도 역전에 대한 고찰
이론적으로 $V=50$일 때, Prim의 연산 횟수는 $O(V^2)$이므로 약 2,500번에 비례합니다. 반면 희소 그래프($E=100$)에서 Kruskal은 $O(E \log E)$이므로 약 660번에 비례하여 Kruskal이 더 빨라야 합니다. 
하지만 실제 측정 결과 희소 그래프에서도 Prim(9.60 us)이 Kruskal(13.80 us)보다 약간 더 빨랐습니다. 이는 $V=50$이라는 규모가 워낙 작아 $V^2$ 탐색에 걸리는 절대적인 시간이 매우 짧은 반면, Kruskal 알고리즘의 초기 간선 추출 및 정렬 함수(`qsort`) 호출에 수반되는 기본 상수항이 더 크기 때문으로 분석됩니다.

## 4. 결론

실험 결과를 통해 다음과 같은 이론적 결론을 도출할 수 있습니다.

1. **희소 그래프 환경:** 정점은 많고 간선이 적은 경우, 공간 복잡도가 $O(V + E)$인 **인접 리스트**를 사용하여 메모리를 아끼고, 정렬 비용이 크지 않은 **Kruskal 알고리즘**을 사용하는 것이 이론적으로 유리합니다.
2. **밀집 그래프 환경:** 간선의 수가 최대치($V^2$)에 근접하게 많은 경우, 간선 증가에 따라 메모리와 정렬 시간이 폭증하는 인접 리스트와 Kruskal 알고리즘은 비효율적입니다. 따라서 공간을 $O(V^2)$으로 고정시키고, 실행 시간도 $O(V^2)$으로 일정하게 유지하는 **인접 행렬과 Prim 알고리즘**을 사용하는 것이 적절합니다.
