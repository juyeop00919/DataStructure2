## 2. 두 탐색 방법의 성능 차이 분석
탐색 과정만 놓고 보았을 때, **순차 탐색은 평균 96.02회**, **이진 탐색 트리(BST) 탐색은 평균 8.32회**의 비교가 발생하여 **BST가 약 10배 이상 빠른 성능**을 보였습니다. 

* **순차 탐색의 한계:** 순차 탐색은 배열의 첫 번째 원소부터 하나씩 모두 비교해야 합니다$(O(N))$. 이번 실험의 탐색 키 50개 중 대부분이 'Not Found(탐색 실패)'였기 때문에, 배열의 끝까지 무의미한 탐색을 진행해야 했고 그 결과 평균 비교 횟수가 전체 데이터 크기인 100에 가깝게(96.02) 측정되었습니다.
* **BST 탐색의 효율성:** 반면 BST는 노드를 방문할 때마다 대상 값의 크기를 비교하여 탐색 범위를 절반씩 줄여나갑니다$(O(log N))$. 따라서 데이터가 배열에 무작위로 섞여 있더라도, 단 몇 번의 비교만으로 해당 숫자의 존재여부를 빠르게 결론을 내릴 수 있었습니다.

<br>

## 3. '트리 생성 비용'을 고려한 종합 성능 분석
BST는 탐색이 빠르다는 장점이 있지만, 사전에 데이터를 삽입하며 올바른 위치를 찾아 구조를 만드는 데(생성 비용) 큰 비용이 발생합니다. 본 실험에서도 트리를 구성하기 위해 **752회의 비교 연산**이 미리 수행되었습니다. 배열은 그냥 순서대로 집어넣으면 되므로 이 비용이 **0**입니다. 

하지만 **생성 비용을 포함한 전체 연산 비용**을 계산해 보면 다음과 같은 결과가 나옵니다.
* **순차 탐색 전체 비용:** 0(생성) + 4,801(탐색) = **4,801회**
* **BST 전체 비용:** 752(생성) + 416(탐색) = **1,168회**

**[결론]** 트리를 만들 때 752번의 비용이 발생했지만, 탐색을 50회 반복하고 나니 전체 비용은 배열을 사용할 때의 **약 4분의 1(24%) 수준으로 대폭 감소**했습니다. 즉, 탐색을 단 1~2번만 할 것이라면 배열이 유리할 수 있으나, **데이터를 여러 번 반복해서 검색해야 하는 환경이라면 초기에 비용을 들여서라도 이진 탐색 트리를 구성하는 것이 효율적**임을 알 수 있습니다.

<br>

## 4. 이진 탐색 트리의 구조에 따른 탐색 성능 변화 분석
이진 탐색 트리는 **가장 처음에 삽입되는 데이터(루트 노드)와 삽입 순서에 따라 트리의 모양이 결정되며, 이 모양이 탐색 성능을 크게 좌우**합니다. 

실험 데이터의 생성 과정을 살펴보면, **최초로 생성된 숫자(루트 노드)가 '939'**로 0~1000 사이에서 매우 큰 값이었습니다. 
이로 인해 이후에 들어오는 939보다 작은 90여 개의 데이터들은 모두 **루트 노드의 '왼쪽 서브 트리'로 쏠려버리는 편향트리 구조**를 보였습니다.

* 만약 이상적인 형태인 **'완전 균형 이진 트리'**로 구성되었다면, 100개의 데이터 탐색 시 평균 약 6.64회 정도의 비교만으로 탐색이 가능했을 것입니다. 
* 본 실험에서는 한쪽으로 트리가 기울어진 구조적 한계 때문에 이상적인 수치보다는 약간 더 높은 **평균 8.32회**의 탐색 비용이 발생했습니다. 

결과적으로 이번 실험을 통해 **이진 탐색 트리는 순차 탐색보다 훨씬 빠르지만, 입력되는 데이터의 순서에 따라 트리가 비대칭적으로 자라나면 최적의 성능을 100% 발휘하지 못할 수 있다**는 특성을 알 수 있었습니다.
